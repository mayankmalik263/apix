Correction 01 · the deck currently says the opposite

India does publish an airfare index. We were about to tell a MoSPI judge it doesn't.

MoSPI publishes “Air fare [normal]: economy class [adult]” — weight 0.08, Base 2012=100, All-India Combined, monthly, in the CPI press-release Annex-V key-items table. We recovered 12 monthly observations from press releases already sitting on disk.

Our extractor reproduces MoSPI's own published inflation rates to the decimal — 8.29 / 7.79 / 3.16 / 4.38 / 8.24 / 8.56 — which is how we know it's right. This is better for us, not worse. The corrected pitch:

India measures every airfare in the country with one number, at weight 0.08, national level only, once a month. That number fell 4.4% in a single month, and its year-on-year rate swung from 3.16% to 8.56% inside five months. One monthly draw cannot describe a market that reprices hourly across 1,100 city pairs. We produce 30 route-level observations a day.

That survives a judge who knows their own publications. “Nothing exists” does not.

Correction 02 · unverified numbers, currently in the demo script

The state-level CPI statistics cannot be traced to any file we hold

The build plan cites item code 294, COICOP 07.3.3.1.2.01, a state spread of 376.09 points, Punjab 432.69, Andhra Pradesh 56.60, Sikkim exactly 100.00, σ = 7.54%, and a −17.8% fall in March 2025. None of those figures appear in any of our 491 downloaded CSVs. They may be perfectly real and simply not downloaded yet. But until someone opens a source and shows the figure, they do not go on a slide and they do not open the demo. Use Correction 01 instead: it's ours, it's verified, and we can show the file it came from.

Correction 03 · decided

The index base period: the real series starts at 100 today

The base is the mean of the first daily medians, and our only real data starts today. So the real APIx is based on 3 September and gives two genuine points — the 3rd and the 4th. The 91-day simulated history renders as a separate, visibly different line and never anchors the real series.

“Our real index starts at 100 today. The line behind it is simulated from a documented model, and it's drawn differently for that reason.”

Nothing real is ever anchored to a simulated number. That's a sentence a judge cannot attack.

Correction 04 · already handled in code, don't undo it

Route weights are provisional, and the system says so on every row

Our six routes carry equal weights because we don't have DGCA city-pair passenger data. The code knows: every index value it produces is stamped weights_provisional = true.

Do not hand-type weights to make the flag disappear. “Our weights are provisional pending DGCA traffic data, and the system marks every affected value” is a strength in front of a statistical office. An invented weight that a judge probes is fatal.

Bharat's loader reads these. It never writes them.

Bharat → Mayank

The API reads Gold, and column names are frozen

Mayank's FastAPI layer queries gold_apix_daily and gold_route_index_daily. If Bharat renames a column, he says so in the group immediately. A renamed column at 4am is a dead demo.

Everyone

The status vocabulary is frozen at seven

apix/vocab.py is committed and is the contract: OK, SOLD_OUT, NO_SERVICE, SOURCE_DISALLOWED, FETCH_FAIL, BLOCKED, PARSE_FAIL — across three classes: MARKET (the market spoke), POLICY (we chose not to collect), SYSTEM (we failed). Nobody adds an eighth. If you think you need one, it's a bug in your parsing.

SQLite now, Postgres on paper

We build and demo on SQLite. Stated plainly: Docker is not installed on the build machine, and neither is WSL2. Installing both means two reboots and a BIOS virtualisation check, 24 hours before a demo that must run ten times. Not a risk worth taking for zero marks.

Bharat also commits db/schema.postgres.sql — the same tables written properly for PostgreSQL, using what SQLite hasn't got: JSONB with a GIN index for raw payloads, NUMERIC(10,2) for money instead of float, TIMESTAMPTZ, real CHECK constraints on the status vocabulary, and true schemas instead of name prefixes.

That file isn't decoration. It's the answer to “why SQLite?”:

SQLite is our demo profile because it installs nowhere and cannot fail on stage. Postgres is the production target — here is the schema, and here is exactly what changes. The application code is unchanged because it goes through SQLAlchemy.

That answer scores. “We used SQLite because it was easy” does not.

Block A
2 h

METHODOLOGY.md v0.1 — the whole spec, with subscripts

  • Cell median: P(r,w,t) = median{ fare : status=OK, not outlier }
  • Price relative: R(r,w,t) = P(r,w,t) / P(r,w,0), base = mean of first 7 daily medians, base period = 100
  • Route index: geometric mean across the 5 windows — name it: this is a Jevons index, and it's what CPI elementary aggregation uses
  • National: APIx(t) = Σ ω·I(r,t) with fixed weights — name it: Laspeyres-type, revised annually not daily
  • Outlier rule: modified Z-score on MAD, threshold 3.5, per cell. Say whose method it is (Iglewicz & Hoaglin) and why not mean ± 3σ.
